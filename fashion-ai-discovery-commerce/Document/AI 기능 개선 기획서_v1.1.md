## 1. 기획 배경

### 1.1 현재 상황

현재 대부분의 패션 커머스 플랫폼은 협업 필터링 기반의 추천 시스템을 운영하고 있습니다. 이는 사용자의 과거 행동 데이터를 기반으로 유사한 상품을 추천하는 방식입니다.

**주요 문제점:**

- 사용자가 한 번 클릭한 스타일/브랜드 위주로만 반복 추천
- 새로운 카테고리나 스타일 발견 기회 부족
- 추천 결과의 다양성 부족으로 인한 탐색 피로도 증가

### 1.2 사용자 불만 사례

29CM와 무신사 사용자들의 실제 VOC(Voice of Customer):

|플랫폼|사용자 의견|
|---|---|
|**29CM**|"파사드패턴 한 번 봤더니 계속 비슷한 브랜드만 나와요"|
|**29CM**|"취향이 바뀌었는데 추천은 그대로예요"|
|**무신사**|"로맨틱, 걸리시 스타일은 추천 안 해줘요"|
|**무신사**|"맨날 같은 옷만 랭킹에 있어요"|

### 1.3 비즈니스 영향

필터버블 현상이 비즈니스에 미치는 부정적 영향:

1. **탐색 피로도 증가** → 앱 이탈률 상승
2. **신규 브랜드 노출 감소** → 판매자 불만 및 입점 이탈
3. **구매 다양성 감소** → 객단가 정체
4. **장기 고객 이탈** → 경쟁 플랫폼으로 이동

무신사 자체 조사 결과(2024.08), 랭킹에 대한 부정/중립 반응이 18%에 달하며, 이 중 12.4%가 "계속 보는 것만 보는 느낌"이라는 부정적 피드백을 남겼습니다.

## 3. 솔루션 개요

### 3.1 핵심 아이디어

**RAG(Retrieval-Augmented Generation) 기반 탐색적 추천 시스템**

기존 협업 필터링의 "유사도 기반 추천"에 "다양성 보장 메커니즘"을 결합하여, 사용자와의 대화 맥락을 분석해 동적으로 추천 비율을 조정합니다.

**✅ 현재 구현 상태**: 핵심 아이디어 완전 구현 완료

### 3.2 작동 원리 (실제 구현 기준)

```
사용자 대화 입력
    ↓
의도 분석 (GPT-4o-mini + Few-shot learning) ✅
    ↓
SQL 벡터 검색 (PostgreSQL/SQLite JSONB) ✅
    ↓
MMR 알고리즘으로 결과 통합 ✅
    ↓
재추천 방지 필터링 (최근 5회, 브랜드 제한, 스타일 다양성) ✅
    ↓
LLM이 추천 이유 생성 (GPT-4o-mini) ✅
    ↓
대화형 추천 결과 제시 ✅
```

### 3.3 차별화 포인트

|기존 시스템|개선 시스템|구현 상태|
|---|---|---|
|유사도 점수만 최적화|유사도 + 다양성 점수 균형|✅ 완료 (MMR 알고리즘)|
|정적 추천 (항상 같은 비율)|동적 추천 (대화 맥락에 따라 비율 조정)|✅ 완료 (Intent 기반)|
|추천 이유 없음|AI가 추천 이유를 자연어로 설명|✅ 완료 (GPT-4o-mini)|
|단방향 추천|양방향 대화로 취향 탐색|✅ 완료 (챗봇 인터페이스)|

### 4.2.4 MMR Algorithm

**역할:** 유사도와 다양성의 균형 보장

**수식:**

```
MMR = λ × Similarity(q, d) - (1-λ) × max Similarity(d, d')
                                        d'∈R

q: 쿼리 (사용자 취향)
d: 후보 상품
R: 이미 선택된 추천 결과
λ: 유사도/다양성 가중치 (기본 0.7)
```

**작동 방식:**

1. 첫 번째 상품: 유사도 점수가 가장 높은 상품 선택
2. 두 번째 이후: 유사도는 높지만, 이미 선택된 상품과는 다른 상품 선택
3. 브랜드 다양성 체크: 동일 브랜드 최대 2개 제한 ✅
4. 스타일 다양성 강제: 최소 3개 다른 스타일 보장 ✅
5. 10개 선택 완료까지 반복

**예시:**

```
[선택 과정]
1번: 검정 후드티 (유사도 0.95)
2번: 네이비 후드티 (유사도 0.93) ✗ → 너무 비슷
     → 카키 워크 재킷 (유사도 0.78) ✓ → 선택
3번: 미니멀 맨투맨 (유사도 0.82, 다양성 확보) ✓
```

**기술 스택 (실제 구현):**

- Python: NumPy, SciPy
- 커스텀 MMR 구현
- 구현 위치: `ml/mmr_algorithm/mmr_scorer.py`

**추가 구현 사항:**
- ✅ 브랜드 다양성 제한 (동일 브랜드 최대 2개)
- ✅ 스타일 다양성 강제 (최소 3개 다른 스타일)
- ✅ 재추천 방지 (최근 5회 대화 제외)
- ✅ 클릭 안 한 상품 제외

**역할:** 추천 이유를 자연어로 생성

**프롬프트 구조:**

```

- 사용자의 기존 취향: {user_style_profile}
- 상품의 스타일: {product_style}
- 유사도 점수: {similarity_score}
- 추천 유형: {recommendation_type}

규칙:
1. 탐색적 추천은 "새로운 발견"으로 프레이밍
2. 왜 이 상품이 사용자에게 어울리는지 구체적으로 설명
3. 다른 고객의 구매 패턴을 활용해 신뢰감 형성

```

**생성 예시:**

|추천 유형|생성된 설명|구현 상태|
|---|---|---|
|**기존 취향**|"평소 좋아하시는 스트릿 스타일이에요. 12,500명이 구매했고, '핏이 예뻐요'라는 후기가 많아요."|✅ 완료|

|**탐색적 추천**|"평소 스타일과는 다르지만, 요즘 MZ 사이에서 핫한 워크웨어 스타일이에요! 스트릿 아이템과 믹스매치하면 새로운 무드를 연출할 수 있어요. 한번 도전해보세요! 🔥"|✅ 완료|

**기술 스택 (실제 구현):**

- 구현 위치: `ml/response_generator/response_generator.py`

### 10.3 ROI 분석

