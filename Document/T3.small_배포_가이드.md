# AWS EC2 T3.small 배포 가이드

## 📊 T3.small 사양 분석

### 인스턴스 사양
- **vCPU**: 2 코어
- **RAM**: 2GB
- **Network**: Up to 5 Gbps
- **EBS Bandwidth**: Up to 2,047 Mbps
- **성능**: Burstable (베이스라인 성능 + 버스트 가능)

### 프로젝트 메모리 요구사항 분석

#### 1. Backend (FastAPI + Uvicorn)
- **예상 메모리**: 150-250MB
- Python 런타임 + FastAPI 애플리케이션
- ML 라이브러리 (numpy, scipy, scikit-learn): ~200MB (import 시)
- **최적화 후**: 150-200MB

#### 2. Frontend (React 빌드 파일)
- **메모리**: 거의 없음 (정적 파일)
- Nginx가 서빙하므로 메모리 사용 없음
- **빌드 크기**: ~5-10MB (압축 후)

#### 3. 데이터베이스
- **SQLite (권장)**: ~10-50MB
- **PostgreSQL**: ~150-200MB
- 현재 프로젝트는 SQLite 기본 설정
- **권장**: SQLite 사용 (메모리 절약)

#### 4. Redis (세션 관리)
- **예상 메모리**: 50-100MB
- 세션 데이터만 저장하므로 메모리 사용 적음
- **최적화 후**: 30-50MB

#### 5. Nginx (리버스 프록시)
- **예상 메모리**: 20-30MB
- 정적 파일 서빙 + 프록시

#### 6. 시스템 오버헤드
- **예상 메모리**: 300-400MB
- OS, 시스템 서비스 등

## 📝 배포 단계별 가이드

### 1단계: EC2 인스턴스 준비

```bash
# Ubuntu 22.04 LTS AMI 사용 권장
# 보안 그룹 설정:
# - SSH (22): 본인 IP
# - HTTP (80): 0.0.0.0/0
# - HTTPS (443): 0.0.0.0/0 (SSL 인증서 적용 시)
# - API (8000): 필요시
```

### 2단계: 필수 패키지 설치

```bash
# 시스템 업데이트
sudo apt update && sudo apt upgrade -y

# Docker 설치
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh
sudo usermod -aG docker $USER

# Docker Compose 설치
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose

# 로그아웃 후 재로그인 또는
newgrp docker
```

### 3단계: 프로젝트 클론 및 설정

```bash
# 프로젝트 디렉토리 생성
mkdir -p ~/fashion-ai
cd ~/fashion-ai

# Git 클론 (또는 파일 업로드)
git clone <your-repo-url> .

# 환경 변수 설정
cd backend
cp .env.example .env  # 또는 직접 생성
nano .env
```

### 4단계: 환경 변수 설정 (backend/.env)

```env
# API 설정
API_HOST=0.0.0.0
API_PORT=8000
DEBUG=False

# 보안
SECRET_KEY=<강력한-랜덤-문자열-생성>

# 데이터베이스 (SQLite 사용 - 메모리 절약)
DATABASE_URL=sqlite:///./fashion_ai.db

# Redis
REDIS_URL=redis://redis:6379

# OpenAI API
OPENAI_API_KEY=<your-openai-api-key>
OPENAI_MODEL=gpt-4o-mini
EMBEDDING_MODEL=text-embedding-3-large
EMBEDDING_DIMENSIONS=3072

# CORS
ALLOWED_HOSTS=["*"]  # 프로덕션에서는 도메인 지정 권장
```

### 5단계: 최적화된 docker-compose.yml 사용

프로젝트 루트에 `docker-compose.t3small.yml` 파일이 있습니다. 이 파일은 T3.small에 최적화된 구성입니다.

**주요 변경사항:**
- ❌ PostgreSQL 제거 → SQLite 사용
- ❌ Weaviate 제거 → SQL 기반 벡터 스토어 사용
- ❌ Prometheus/Grafana 제거 → 메모리 절약
- ✅ Redis 메모리 제한 설정 (80MB)
- ✅ 각 서비스별 메모리 제한 설정

### 6단계: Nginx 설정 확인

`nginx/nginx.conf`와 `nginx/conf.d/default.conf` 파일이 있는지 확인하세요.
이미 프로젝트에 포함되어 있습니다.

### 7단계: Frontend 빌드

```bash
cd frontend
npm install
npm run build
cd ..
```

빌드된 파일은 `frontend/build` 디렉토리에 생성됩니다.
Nginx가 이 디렉토리의 정적 파일을 서빙합니다.

### 8단계: 배포 실행

**방법 1: 배포 스크립트 사용 (권장)**

```bash
# 배포 스크립트 실행
./deploy-t3small.sh
```

**방법 2: 수동 배포**

```bash
# Docker 이미지 빌드 및 실행
docker-compose -f docker-compose.t3small.yml up -d --build

# 로그 확인
docker-compose -f docker-compose.t3small.yml logs -f

# 서비스 상태 확인
docker-compose -f docker-compose.t3small.yml ps

# 메모리 사용량 확인
docker stats
```

## ⚠️ 주의사항 및 제한사항

### 1. 동시 접속자 수 제한
- T3.small의 제한된 리소스로 인해 **동시 접속자 수는 50-100명 정도**로 제한
- 트래픽이 많아지면 T3.medium 이상으로 업그레이드 고려

### 2. 버스트 성능
- T3 인스턴스는 CPU 크레딧 기반
- 지속적인 고부하 시 CPU 크레딧 고갈 가능
- 모니터링 필요

### 3. 스왑 메모리 설정 (권장)
```bash
# 스왑 파일 생성 (1GB)
sudo fallocate -l 1G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 영구적으로 활성화
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

### 4. 모니터링 설정
```bash
# 시스템 리소스 모니터링
sudo apt install htop
htop

# 또는 Docker stats
docker stats
```
